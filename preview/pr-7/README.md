## 限界開発とは

限界開発は、**スマートフォン1台しか持たず、精神・肉体・金銭・時間・生活上の問題を抱え、プログラムも分からない人間が、AIと根性だけで生活をぶん回す仕組みを作る社会実験プロトコル**です。

生活が安定してから開発を始めるのではありません。

生活が崩れかけている最中に、AIを相談相手、設計者、実装補助、監査役、記録係として使い、仕事・収入・生活を止めないための仕組みを一つずつ作ります。

このリポジトリの主役は、特定のアプリやデバッグ機能ではありません。

> **制約だらけの人間が、必要な技術・手順・道具・運用をその場で獲得し、どこまで自分の生活を再構築できるか。**

その過程そのものが限界開発です。

## 開始条件

- 実質スマートフォン1台
- PC、高額な機材、大きな初期投資を前提にしない
- 心身の状態が安定しているとは限らない
- 長時間集中できるとは限らない
- 無料枠や弱いサーバーを使う
- プログラム素人から始める
- それでも生活と仕事は待ってくれない

限界は例外条件ではなく、最初から設計へ組み込む前提条件です。

## 社会実験プロトコル

1. **困る**  
   生活や仕事の詰まりを、誤魔化さず観測する。
2. **AIと分解する**  
   感情、事実、作業、判断、制約を分ける。
3. **最小の仕組みにする**  
   今日の詰まりを一つ減らす道具、手順、記録を作る。
4. **自分の生活で使う**  
   実際に使い、壊し、直し、また使う。
5. **公開して知識にする**  
   成功だけでなく、失敗、停止、再開方法、限界も残す。
6. **仕事・収入・生存へ接続する**  
   技術を飾りにせず、生活を維持する力へ変える。

## ここから生えたもの

### RTS

AIに丸投げせず、仕様、判断、実行、監査、検証、引き継ぎを残すための共通開発基盤です。

### Vlog Wizard

既存の動画編集ソフトで挫折したため、「撮る、並べる、喋る、確認する、出す」をスマホ中心で通すために作り始めた動画制作システムです。

### 限界開発式デバッグエンジン

人力で全画面へ体当たりし続けて潰れないよう、一度踏んだ不具合を再現テストと共通ナレッジへ変換する生命維持装置です。

### 視覚ナビゲーションマップ

各画面のスクリーンショットとボタンの接続先を線で結び、UIがどこにつながっているかを視覚的に監査します。

これらは限界開発そのものではなく、**限界状態でも開発と生活を継続するために必要になって生えた部品**です。

## このリポジトリに残すもの

- 何に困っていたか
- 体調、資金、端末、時間などの制約
- AIとの相談と判断
- 仕様と、今回やらないこと
- 実装と接続構成
- 自動テストと人間による確認
- 踏んだ不具合と修正
- 動かなかった理由
- 停止後に再開するための引き継ぎ
- 公開物と自己責任範囲
- 仕事や収入へどう接続したか

## 基本原則

- スマホを司令塔にする
- できないことを隠さない
- 未確認を確認済みと書かない
- AIの提案に反論し、設計判断を人間が持つ
- 万能な完成品より、今日使える最小単位を優先する
- 失敗を消さず、再現可能な知識へ変える
- 一度踏んだ不具合は、なるべく人間が二度踏まなくてよい形にする
- 公開開発へ秘密情報を持ち込まない
- 危険な状態や苦痛を美化しない
- 完成より、再開可能性を重視する

## 「成功」の定義

成功は、立派なプロダクトを完成させることだけではありません。

- 今日の作業が一つ減った
- 途中で止まっても再開できた
- 同じ失敗を自動テストへ変えた
- 他人が同じ手順を追試できた
- 仕事や収入につながる接点が一つ増えた
- 生活を一日長く維持できた

これらも限界開発の成果です。

## 成功物語にはしない

動いていないものは未確認、失敗したものは失敗、体調や生活上の理由で止まったものは停止として残します。

一方で、限界状態を我慢して開発することを推奨する企画でもありません。現実の制約を隠さず、安全線を引きながら、生存可能性を増やすための社会実験です。

## 安全と本番利用

公開開発では、個人情報、認証情報、医療・介護情報、社外秘、実在顧客データを扱いません。

サンプルで動いたことと、本番運用できることは別です。本番導入前には、権限、保存、バックアップ、外部サービス、規約、セキュリティ、費用、運用担当を改めて確認します。
