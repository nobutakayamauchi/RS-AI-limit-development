# 限界開発を再現するための環境と前提条件

このページでは、限界開発と同じような開発環境・進め方を再現したい人向けに、実際に使用している構成、必要な役割、接続方法、置き換え方、注意点をまとめます。

限界開発は、すべての処理をスマートフォン本体だけで実行する方法ではありません。

**スマートフォンを司令塔として、AI、GitHub、クラウド実行環境、公開ページ、記録媒体を一つの開発フローとして接続する方法**です。

---

## 1. 現在の実構成

現在の限界開発では、主に次の構成を使用しています。

```text
iPhone
  ├─ ChatGPT / Codex
  │    ├─ 問題分解
  │    ├─ 仕様化
  │    ├─ 実装支援
  │    └─ レビュー・文書化
  ├─ GitHub
  │    ├─ ソースコード
  │    ├─ 仕様書・テンプレート
  │    ├─ Pull Request
  │    └─ GitHub Pages
  ├─ Termius
  │    └─ SSH
  │         └─ Oracle Cloud 上の Ubuntu
  │              ├─ Python・CLI実行
  │              ├─ テスト
  │              ├─ Git操作
  │              ├─ ログ確認
  │              └─ 環境更新・再起動
  ├─ Safari
  │    └─ GitHub Pages・試作品の実機確認
  ├─ note
  │    └─ 開発記録・失敗・改善の文章化
  └─ X
       └─ 日々の進捗・告知・相談受付
```

スマートフォン本体だけで計算やテストを完結させるのではなく、スマートフォンから外部サービスとクラウド環境を操作し、全工程を接続しています。

---

## 2. 各ツールの役割

### iPhone

中心となる操作端末です。

- AIとの対話
- GitHubの確認・操作
- SSH接続
- 公開ページの実機確認
- note・Xでの記録と告知

### ChatGPT / Codex

- ヒアリングと問題分解
- 要件整理と仕様書作成
- 実装案・コード作成
- 修正・レビュー
- テスト案と文書作成

### GitHub

- ソースコード管理
- 仕様書・テンプレート管理
- Issue・Pull Request
- 判断履歴と変更履歴
- GitHub Pagesによる公開

### Oracle Cloud（Ubuntu）

テスト・実行環境として使用します。

- Pythonや各種CLIの実行
- 自動テスト
- ログ確認
- ライブラリ・OS更新
- Git操作
- 必要に応じた再起動・環境確認

### Termius

iPhoneからOracle CloudへSSH接続するためのクライアントです。

- SSH接続
- コマンド実行
- ログ確認
- 更新・再起動
- テスト環境の操作

### GitHub Pages

- トップページ
- 仕様・再現資料
- 試作品
- PDFや公開資料

を公開する場所です。

### RTS

限界開発を支える共通開発基盤です。

- 仕様管理
- 判断記録
- ガバナンス
- 実行制御
- テスト記録
- リスク確認
- 引き継ぎ
- 学習結果の蓄積

### note / X

- note：背景、失敗、改善、考え方を文章として残す
- X：日々の進捗、告知、相談受付、外部との接点

## 3. 使用するサービスは置き換え可能です

上記は現在実際に使用している構成ですが、限界開発はこれらのサービスを必須とするものではありません。

重要なのは商品名ではなく、**各サービスが担当する役割**です。

| 役割 | 現在使用しているもの | 置き換え例 |
|---|---|---|
| 要件整理・文章作成 | ChatGPT | 他の対話型AI |
| コード作成・修正 | Codex | 他のコード生成AI、IDE、開発支援ツール |
| ソース・仕様管理 | GitHub | GitLab、その他のバージョン管理環境 |
| テスト・実行環境 | Oracle Cloud Ubuntu | 他社クラウド、VPS、自宅サーバー、ローカルPC |
| スマホからのSSH接続 | Termius | 他のSSHクライアント |
| 公開ページ | GitHub Pages | 他の静的ホスティング、Webサーバー |
| 開発記録 | note | ブログ、Webサイト、ドキュメントサービス |
| 告知・相談受付 | X | 他のSNS、メール、問い合わせフォーム |
| 仕様・判断・検証管理 | RTS | Markdown、チェックリスト、他の管理基盤 |

自分が使い慣れているサービス、予算、端末、目的に合わせて置き換えて構いません。

例えば、次のような構成でも再現できます。

- Oracle Cloudではなく別のVPSを使う
- Termiusではなく別のSSHアプリを使う
- GitHub Pagesではなく自分のWebサイトで公開する
- noteではなくブログに記録する
- RTSを使わず、README・仕様書・テスト記録・承認チェックで最小構成を作る

限界開発で再現すべきものは、使用サービスそのものではありません。

**相談、問題分解、仕様化、実装、テスト、確認、記録、公開を、一つの流れとして接続すること。**

この役割が保たれていれば、自分の好きな道具を組み合わせて独自の限界開発環境を構築できます。

## 4. 人間とAIの役割分担

限界開発では、すべてをAIへ丸投げしません。

### 人間が行うこと

- 何に困っているかを決める
- 公開してよい範囲を判断する
- 最低成功条件を決める
- 実際に動いたか確認する
- 本番利用してよいか判断する
- 公開内容を承認する

### AIが行うこと

- 問題の分解
- 要件整理
- 仕様書作成
- 実装案とコード作成
- テスト案作成
- レビューと改善案
- ドキュメント作成

最終判断と承認は人間が行います。

---

## 5. 基本フロー

1. 困っている作業を一つ決める
2. 公開可能な情報だけに切り分ける
3. 現在の業務を分解する
4. 最低成功条件を決める
5. 仕様書を作る
6. 専用ブランチで実装する
7. Oracle Cloudなどの実行環境でテストする
8. スマートフォンで実機確認する
9. 確認済み事項と未確認事項を分ける
10. GitHubへ反映する
11. GitHub Pagesまたはリポジトリで公開する
12. note・Xで記録を残す
13. 次の改善へつなげる

---

## 6. 再現時の重要条件

同じAI、同じ端末、同じクラウドを使うことより、次の条件を守ることが重要です。

- 問題を一つに絞る
- 最低成功条件を先に決める
- 実在データや機密情報を公開環境へ持ち込まない
- 未確認事項を事実として扱わない
- 試作品と本番利用を区別する
- 判断記録を残す
- 失敗と修正も記録する
- 人間が最終承認する

---

## 7. 再現しやすい最小構成

最初から現在の構成をすべて揃える必要はありません。

最小構成は次の通りです。

- スマートフォンまたはPC
- AIチャット
- GitHubなどの管理場所
- 1つのREADME
- 1つの仕様書
- 1つのテスト記録
- 1つの試作品
- 1つの公開ページ

サーバー実行が必要な場合だけ、Oracle Cloudや別のVPS、ローカルPCなどを追加します。

まず一案件を最小構成で最後まで通し、その後に必要な役割だけを追加することを推奨します。

---

## 8. 向いている人

- プログラミング未経験だが、業務改善を形にしたい人
- スマートフォン中心で開発を進めたい人
- AIを使って小さな仕組みを作りたい人
- 完成品だけでなく、開発過程も残したい人
- 個人または小規模で運用したい人
- 自分の好きなツールを組み合わせて環境を作りたい人

---

## 9. 向いていないケース

- 機密情報を公開環境へ持ち込みたい
- 人間確認なしで自動実行したい
- 最初から本番品質を保証したい
- 大規模組織の基幹システムをすぐ作りたい
- 要件が定まっていないまま実装だけ進めたい
