# Visual Map Split Decision

## 決定

画面遷移の監査は、全体マップ1枚だけに依存しない。

- 全体マップ: システム全体の構造、孤立画面、戻り道、主要導線を確認する
- 画面別マップ: 1画面を起点に、その画面の各ボタンがどこへ接続するかを確認する

## 理由

トップ画面やハブ画面から複数の接続が出ると、線の重なりによって次の問題が起きる。

- ボタンと接続先の対応が読めない
- 想定接続先と実測接続先の不一致を見落とす
- 別画面から来た線と混同する
- 1枚絵を見ても修正対象を特定できない

したがって、接続密度または交差が閾値を超えた時点で、全体マップは概要専用とし、判定は画面別マップで行う。

## 自動分割条件

- 接続総数 >= 8
- 単一画面の出力接続数 >= 3
- 推定線交差数 >= 2
- 明示的な強制分割

## リリースゲート

リリース前には次を両方確認する。

1. 全体マップで主要導線と到達可能性を確認
2. 画面別マップで各ボタンの期待接続先と実測接続先を確認

全体マップが読みにくい場合、読みづらさを許容して判定を続けてはならない。画面別マップへ切り替える。
