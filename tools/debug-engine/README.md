# 限界開発式デバッグエンジン v0.1

## 目的

人間が行った通常操作・偶発的誤操作・意図的破壊操作を、再現可能なテスト資産へ変換する。
一度踏んだ不具合を回帰テストとして保存し、リリース前に自動実行する。
自動化できない感覚評価だけを、人間向けチェックリストとして残す。

## 発火地点

### 1. REPORT_INGEST（随時）
不具合報告、会話ログ、操作メモを受け取った時に発火する。

処理:
- 文面から操作意図を分類
- 確認目的を抽出
- 既存ナレッジとの類似判定
- 新規候補または既存項目更新案を生成

### 2. REPRODUCTION（修正前）
不具合修正へ入る前に発火する。

処理:
- 再現手順を固定
- 期待結果と実結果を分離
- 証拠（スクリーンショット、ログ、通信、状態）を収集
- 再現できなければ修正へ進まない

### 3. REGRESSION（修正後）
修正を加えた直後に発火する。

処理:
- 元の再現シナリオを再実行
- 正常導線を再確認
- 類似画面・類似状態へ横展開
- 合格したシナリオを回帰テストへ登録

### 4. RELEASE_GATE（リリース前・必須）
限界開発で成果物を公開・リリースする直前に発火する。

処理:
- 共通回帰テスト
- 対象プロジェクト固有テスト
- 破壊操作テスト
- データ保持・復旧テスト
- 自動化不能項目の人間チェック票生成

重大項目が失敗した場合、リリースを停止する。

### 5. KNOWLEDGE_PROMOTION（テスト終了後）
同じ目的・欠陥が複数箇所で確認された時に発火する。

処理:
- 単発事例を共通テストへ昇格
- 適用対象を画面単位から状態・機能単位へ拡張
- ナレッジの根拠、発生件数、再現率を記録

## 操作意図の分類

- `NORMAL_FLOW`: 通常操作
- `ACCIDENTAL_MISUSE`: 意図せず行った誤操作
- `DESTRUCTIVE_TEST`: 壊れる可能性を意図的に確認
- `RECOVERY_TEST`: 離脱、復帰、再実行、復元
- `STRESS_TEST`: 連打、反復、長時間、同時操作
- `STATE_MISMATCH`: 表示状態と内部状態の不一致
- `DATA_LOSS_RISK`: 編集内容・保存データ消失の危険
- `HUMAN_ONLY`: 感覚・理解・自然さなど自動判定困難

分類は単一選択ではなく複数付与を許可する。確信度と根拠文を必ず保存する。

## 共通目的

1. 操作が実際に受理されること
2. 重複操作で二重実行されないこと
3. 非同期処理中の離脱・復帰に耐えること
4. 表示と内部状態が一致すること
5. 保存・復元・再編集で内容が消えないこと
6. エラー後に安全に再実行できること
7. プレビューと最終成果物が一致すること
8. 意図しない順序で操作しても破綻しないこと
9. 修正が別の正常導線を壊さないこと
10. 人間にしか評価できない項目を漏らさないこと

## 共通テスト項目への昇格条件

次のいずれかを満たした項目は共通ナレッジ候補とする。

- 異なる2画面以上で同じ目的の不具合が発生
- 同じ不具合が3回以上再現
- データ消失、誤完了、操作不能、進行不能に関わる
- リリース後の復旧が困難
- 人間が毎回同じ確認を繰り返している

候補は根拠付きでレビューし、承認後に `knowledge/common-tests.yaml` へ追加する。

## 人間に残すテスト

自動テスト完了後、通常のデバッガー視点から以下を出力する。

- 初見で次の操作を理解できるか
- 押しやすさ、誤操作しにくさ
- 状態表示が直感と一致するか
- 毎回の操作が強いストレスにならないか
- 動画・画像・音声の自然さ
- 音ズレ、音量バランス、ピー音位置
- 完成物として見苦しくないか

「確認してください」だけで終わらせず、前提、操作、観察点、合否基準を含むテストプログラムとして生成する。
