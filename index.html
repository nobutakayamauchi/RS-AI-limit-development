限界開発

スマホ1台、AIと根性。
生活が詰まるたび、必要な仕組みをその場で生やす。

これは「最強の開発環境を作る企画」ではありません。制約だらけの人間が、AIを生活インフラとして使い、生活・仕事・収入・生存をどう再構築できるかを記録する社会実験です。

限界は完成条件ではなく、開始条件。
限界開発とは現在の開発環境記録を読む
DEFINITION — FIXED

定義は変えない。

限界開発とは、スマートフォン1台しか持たず、精神・肉体・金銭・時間・生活上の問題を抱え、プログラム素人である人間が、AIと根性だけで生活をぶん回す仕組みを作る社会実験です。

RTSも、Vlog Wizardも、デバッグエンジンも、Obsidianも主役ではありません。必要になったから生えた生命維持設備です。環境が巨大化しても、主語は「限界状態の人間が生活を回せるか」のままです。

STARTING CONDITIONS

普通なら「準備してから始める」条件で、始める。

01 / DEVICE

実質スマホ1台

PC、高額機材、強いローカルマシンを前提にしない。スマホは司令塔としてAI、GitHub、SSH、クラウドを動かす。

02 / HUMAN

人間側が安定しているとは限らない

体力、集中、時間、生活状況は揺れる。だから「中断しない」より「いつでも再開できる」を設計する。

03 / MONEY

金で殴らない

無料枠、弱いサーバー、既存サービスを組み合わせる。制約がアーキテクチャを育てる。

04 / SKILL

素人から始める

コード暗記より、AIと仕様・設計・検証を往復し、必要な技術を必要な時に獲得する。

05 / REALITY

実生活でDogfoodする

デモが動くだけでは足りない。実際のVlog、実際のサーバー、実際の操作で壊して観測する。

06 / TRUTH

未確認を成功にしない

確認済み・故障・古い・未確認を分ける。都合のいい完成物語を作らない。

2026-08 / CURRENT ARCHITECTURE

開発環境は、コード生成から「文脈と証拠の設計」へ進化した。

AIへ全部読ませるほど賢くなるわけではない。必要な文脈だけを正しい場所へ送り、実世界で確認し、人間が判断境界を持つ。そのための基盤がRTSを中心に生えています。

Code existence != runtime evidence.

実dogfoodで、古いソースツリーを「いま動いている実装」と誤認しかけたことから追加された不変条件です。コードがあることと、今それが動いていることは別。

STALE古い・非稼働・重複
UNOBSERVEDまだ観測していない
WHAT GREW OUT OF IT

必要に迫られて、インフラが生えた。

RTS

仕様、ルーティング、実プロジェクト観測、Lifecycle、Release判断を分離する共通基盤。AIが人間判断を勝手に越えない。

Knowledge Bridge / FREEZER

完了した知識を凍結し、必要な時だけ文脈へ戻す。Obsidianは巨大な一枚岩ではなく記憶層として使う。

Vlog Wizard

「撮る、並べる、喋る、確認する、出す」をスマホ中心で一本につなぐために生えた制作基盤。

限界開発式デバッグエンジン

一度踏んだ不具合を、再現シナリオ・回帰テスト・知識へ変換し、人間の再体当たりを減らす。

視覚ナビゲーションマップ

画面・操作・遷移を可視化する。ただし画面やコードの存在をruntime realityとは混同しない。

GitHub Pages / Docs

コードだけでなく、定義、失敗、判断、完成記録、再開地点を公開可能な形で残す。

PROTOCOL

困った瞬間を、次の人が再利用できる知識へ変える。

1

困る

生活・仕事・制作・運用の詰まりを、そのまま観測する。

2

AIと分解する

事実、感情、制約、判断、作業を分ける。

3

文脈を切る

全部を投げず、今回必要な情報だけを正しいAI・正しいプロジェクトへ送る。

4

最小の仕組みにする

人生を一気に直さず、今日の詰まりを一つ減らす。

5

実プロジェクトで使う

デモではなく実物でDogfoodし、Deployment Identityを確定してから観測する。

6

失敗を証拠へ変える

AS_BUILT / BROKEN / STALE / UNOBSERVED を分離し、テストと記録へ戻す。

7

凍結して再開可能にする

完成した判断をFREEZERへ、次回必要な差分だけを残す。

8

生活へ戻す

開発を仕事、収入、時間、生存へ接続する。

HUMAN BOUNDARY

AIは強くする。でも、勝手には決めさせない。

Observationは修復命令ではありません。提案、証拠、判断、実装、Releaseを分け、routing / approval / implementation authorization / release decision は人間側に残します。

やらないこと: 自動修復を成功扱いする、未観測を完成扱いする、古いコードをruntime realityとして断定する、限界状態や苦痛を美化する。
SUCCESS

「完成した」より、「また続きから始められる」。

作業が一つ減る

小さくても生活負荷が減れば成果。

失敗を二度踏まない

不具合が再現可能なテスト・知識になる。

未確認を残せる

分からないものを分かったふりにしない。

再開できる

中断しても現在地と次の一手が残る。

他人が追試できる

社会実験として再現・反証可能にする。

生活へ接続する

仕事・収入・生存へ戻らなければインフラだけが太る。
