現在の開発構成

通常はiPhoneからAI・GitHub・Termiusを操作し、Oracle Cloud上のUbuntuで実行・テスト・ログ確認を行います。通常環境で能力不足になった重処理だけ、毎回の確認後にGoogle Cloudへ逃がします。

iPhone ├─ ChatGPT / Codex ─ 仕様・実装・レビュー ├─ GitHub ─ コード・仕様・履歴・Pages ├─ Termius ─ SSH ─ Oracle Cloud Ubuntu │ ├─ 通常の実行・テスト │ ├─ Security Gate │ ├─ Cost / Consequence Gate │ └─ 承認・監査記録 ├─ Google Cloud ─ 非常用オーバーフロー計算 │ ├─ Artifact Registry │ ├─ Cloud Storage 隔離領域 │ └─ Cloud Run Job（自動実行なし） ├─ Safari ─ 公開ページ・実機確認 ├─ note ─ 開発記録 └─ X ─ 告知・相談受付

Google Cloudは通常基盤ではありません。通常サーバーで完走できない処理を、手動確認後に1回だけ逃がす非常用経路です。各サービスは、同じ役割を果たす別の道具へ置き換えられます。

実行前の絶対ゲート

入力を受け取っただけでは処理を開始しません。画像・動画・音声・文書・アーカイブ・CSV・JSONだけでなく、ファイル名、拡張子、MIME、メタデータ、入力文、URL、マニフェスト、実行引数も未信頼入力として扱います。

INPUT ↓ SECURITY GATE ↓ COST / CONSEQUENCE GATE ↓ EXPLICIT SINGLE-USE APPROVAL ↓ SCOPED EXECUTION ↓ OUTCOME VERIFICATION + AUDIT
Security Gate許可形式、実体MIME、容量、解像度、尺、ストリーム、展開後容量、メタデータ、パス、埋め込み内容を検査。判定不能は隔離・拒否します。
Cost Gate利用先、CPU・メモリ・モデル、最大時間、並列数、再試行、転送・保存、料金上限、外部への影響を表示します。
Approval Gate検査済み入力ハッシュと実行条件へ紐づく、期限付き・1回限りの明示承認だけを受け付けます。
Audit検査結果、見積もり、承認、実行ID、結果、実費、失敗、削除・後片付けまで残します。

入力や条件が変わった場合は、以前の承認を流用せずSecurity Gateからやり直します。有料先への自動フォールバック、自動再試行、自動公開は行いません。

限界開発とは

完成品だけを見せる企画ではありません。相談、仕様化、安全境界、判断、失敗、テスト、費用、承認、未確認事項、次の一手まで残します。

再現すべきものは特定サービスではなく、相談・問題分解・安全確認・仕様化・実装・料金確認・承認・テスト・記録・公開を一つの流れとして接続することです。

今回の制約

スマホ中心PCを前提にせず、スマホからAI開発環境とGitHubを動かします。
時間は有限長期計画より、短時間でも価値を生む最小単位を優先します。
お金を勝手に使わない無料・低コストの道具を優先し、課金経路は上限表示と1回ごとの承認を必須にします。
秘密と未検査入力を持ち込まない実在する顧客情報や社外秘資料を使わず、架空データと検査済み素材で試します。

公開開発の安全線

会社名、顧客名、個人情報、医療・介護情報、社内URL、ID、パスワード、APIキー、実在の顧客データ、非公開の売上情報は扱いません。

サンプル条件で動いたことと、本番導入できることは別です。実務へ導入する場合は、データ形式、入力隔離、権限、保存、バックアップ、規約、セキュリティ、費用上限、運用担当を改めて確認します。
