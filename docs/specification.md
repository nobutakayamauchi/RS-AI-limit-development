# 限界開発 仕様書

## 1. 目的

限界開発は、スマートフォンを操作端末として、AI・GitHub・Codex・RTS・公開ページを接続し、相談、問題分解、仕様化、実装、検証、記録、公開までを一つの流れで回す公開開発方式です。

単発の作品制作ではなく、別の題材でも同じ手順を再現できる状態を目指します。

## 2. 基本原則

- スマホ中心で全工程を接続する
- AIを実装補助だけでなく、整理・設計・検証にも使う
- 最低成功条件を先に決める
- 実在する秘密情報を公開開発へ持ち込まない
- 架空データまたは公開可能な情報だけで試す
- 実行済み、確認済み、未確認を明確に分ける
- 成功だけでなく、失敗、判断、修正履歴も残す
- サンプルで動くことと、本番導入可能であることを区別する

## 3. スマホ1台から全工程をつなぐ

限界開発では、スマートフォンを単なる閲覧端末として使いません。

- 相談内容の整理
- AIとの対話
- 仕様書の作成
- GitHub上のファイル管理
- 実装指示
- Pull Requestの確認
- 試作品の実機テスト
- GitHub Pagesでの公開
- note・Xでの記録と告知

までを、原則としてスマートフォンから接続します。

すべての処理をスマートフォン本体で実行するという意味ではありません。スマートフォンを操作端末として、クラウド上のAI、GitHub、Codex、RTS、公開ページを一つの開発フローとして動かします。

## 4. 開発フロー

1. 安全確認
2. 悩み・目的の聞き取り
3. 現在の作業と判断の分解
4. 理想状態と最低成功条件の定義
5. 仕様書の固定
6. 専用ブランチで実装
7. 架空データでテスト
8. スマホ実機で確認
9. 確認済み事項と未確認事項の記録
10. 公開・引き継ぎ・改善

## 5. 対象にする課題

- コピー、転記、集計、確認、報告などの反復作業
- 外注・スタッフへの説明、確認、修正、進行管理
- 情報整理、テンプレート化、簡易ダッシュボード
- 小規模事業者が一人または少人数で抱える業務上の詰まり

## 6. 対象外

- 本番利用を前提とした無検証の自動化
- 個人情報、医療・介護情報、社外秘、認証情報を含む公開開発
- 実行していない処理を確認済みと表現すること
- 完成保証、売上保証、無条件の本番導入保証

## 7. RTSとの関係

RTSは、限界開発を回すための共通開発基盤です。

仕様管理、判断記録、ガバナンス、実行制御、テスト、引き継ぎ、ログ保存などを共通化し、案件ごとに最初から仕組みを作り直さずに済むようにします。

- [RTS リポジトリ](https://github.com/nobutakayamauchi/RTS)

## 8. 成果物

各回では、必要に応じて次を残します。

- エピソード概要
- 仕様書
- 進行状況
- 実装ファイル
- テスト報告書
- 引き継ぎ書
- 完全記録PDF
- 公開ページ
- 失敗と修正履歴

## 9. 再現性

限界開発では、仕様書・テンプレート・作業手順・PDF資料・試作品・テスト記録・安全基準を同じリポジトリへ集約します。

第三者が同じ資料を読み、別の題材へ置き換えて、同じ流れを追試できる状態を目標とします。
