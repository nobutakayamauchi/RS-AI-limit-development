# 限界開発の構築手順

このページは、限界開発をゼロから立ち上げ、最初の1案件を公開まで通すための実行手順です。

## 0. 先に決めること

- 解決したい作業を1つに絞る
- 公開してよい範囲を決める
- 最低成功条件を1文で定義する
- 本番データではなく架空データを使う
- 最終承認者を人間に固定する

## 1. 最小環境を用意する

- スマートフォン
- 対話型AI
- GitHubアカウント
- コード作業支援AI
- 実行・テスト環境
- ブラウザ
- 公開先

現在の実例では、iPhone、ChatGPT、Codex、GitHub、Termius、Oracle Cloud Ubuntu、GitHub Pages、note、X、RTSを接続しています。

## 2. リポジトリを作る

最低限、次の構成を用意します。

```text
project/
├─ README.md
├─ SAFETY.md
├─ docs/
├─ templates/
├─ episodes/
└─ index.html
```

READMEには目的、対象、制約、現在地を記載します。SAFETYには扱わない情報と本番利用前の確認事項を書きます。

## 3. 相談を作業単位へ分解する

1. 困っている作業を聞く
2. 入力を確認する
3. 判断が必要な箇所を分ける
4. 出力を決める
5. 例外と禁止事項を決める
6. 最低成功条件を固定する

## 4. 仕様書を作る

[仕様書テンプレート](../templates/specification-template.md)を使い、少なくとも次を固定します。

- 目的
- 入力
- 出力
- 制約
- 非対象
- 最低成功条件
- テスト方法
- 未確認事項

## 5. 専用ブランチで実装する

- 変更対象を1機能に絞る
- AIへ仕様書を読ませる
- 実装前に変更ファイル一覧を確認する
- 実装後に差分を確認する
- 直接本番へ書き込まない

## 6. Oracle Cloudでテストする

TermiusからOracle Cloud上のUbuntuへSSH接続し、次を確認します。

- 依存関係の導入
- コマンド実行
- PythonやCLIの動作
- 入出力
- エラー時の挙動
- ログ
- 再実行

## 7. 架空データで検証する

[テスト報告テンプレート](../templates/test-report-template.md)を使い、確認済み、未確認、失敗、残課題を分離します。

## 8. スマホで実機確認する

- 表示崩れがないか
- ボタンが押せるか
- リンクが正しいか
- 説明だけで使い方が分かるか
- 誤解を招く表現がないか

## 9. 公開する

- GitHubへ反映
- GitHub Pagesで公開
- 完成記録を作成
- noteで背景と失敗を記録
- Xで公開告知

## 10. 引き継ぎを残す

作業終了時には、現在地、完了事項、未完了事項、次の一手、注意点を[引き継ぎ書](../episodes/2026-07-31-unhandled-case-report/HANDOFF.md)の形式で残します。

## 完了条件

限界開発の1サイクルは、次を満たした時点で完了です。

- 仕様が残っている
- 試作品が動く
- テスト結果が残っている
- 未確認事項が分離されている
- 公開範囲が確認されている
- 次の担当が再開できる
- 人間が公開を承認している
