限界開発の記録

ここは「デバッグ製品のマニュアル」ではありません。限界開発という社会実験の定義、現在の開発環境、再現方法、実験記録を、現在地と歴史を混同しない形で置く場所です。

限界開発 = スマホ1台しか持たず、生活上の制約を抱えたプログラム素人が、AIと根性だけで生活をぶん回す仕組みを作る社会実験。

まず読む

限界開発 仕様書変えない定義、目的、成功条件、安全境界。現行開発アーキテクチャ文脈設計、RTS、Knowledge Bridge、Deployment Identity、Evidence loop。再現環境スマホ中心で社会実験を追試するための条件と構成。構築手順最小構成から、必要になった分だけ基盤を増やす方法。

現在の生命維持設備

RTS / Knowledge BridgeIdea Routing → Human Decision → Dogfood → Lifecycle → City Release。限界開発式デバッグエンジン一度踏んだ不具合を再現・回帰・知識へ変換する。視覚ナビゲーションマップ画面・操作・遷移を可視化する補助層。安全基準限界状態を美化せず、停止・中断・人間判断を優先する。

現在の重要原則

Context Design全部をAIへ投げない。正本、凍結知識、差分、観測、提案、判断を分離する。
Evidence FirstAS_BUILT / BROKEN / STALE / UNOBSERVED を分離し、未確認を成功扱いしない。
Deployment Identity Firstservice / working directory / entrypoint / active surface等を確認してからruntimeを分類する。
Human Decision BoundaryAIは観測・提案してもrouting、approval、implementation、releaseを勝手に越えない。

歴史記録

Episodeや過去の公開物は、その時点で実際に使っていた構成を残す歴史資料です。現在のRTSやDeployment Identity Gateを後付けで「当時も使っていた」ことにはしません。現在のプロトコルと過去の事実を分けること自体がEvidence Firstです。
