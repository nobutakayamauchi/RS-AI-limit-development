① はじめに

限界開発 仕様書目的、思想、対象課題、公開ルール、スマホから全工程を接続する構成、RTSとの関係。 リポジトリ概要基本方針、ディレクトリ構成、現在のEpisodeと運用方法。 公開開発の安全基準扱わない情報、本番利用前の確認事項、公開と実運用の境界。 AI開発基盤 RTS仕様、判断、ログ、検証、ガバナンスを接続する共通基盤。

② 限界開発を再現する

同じAIや同じ端末を揃えることより、問題を一つに絞り、仕様・検証・人間承認・記録を一つの流れとして接続することを重視します。

再現するための環境と前提条件必要な道具、スマホ1台の意味、人間とAIの役割、基本フロー、最小構成、向いているケース。 限界開発の詳細仕様何を満たせば限界開発と呼べるのか、設計原則と運用境界を確認する。

③ 実際に使うテンプレート

インタビューテンプレート相談内容を安全に聞き取り、課題と公開可能範囲を絞る型。 仕様書テンプレート目的、入力、出力、制約、最低成功条件を固定する型。 テスト報告テンプレート確認済み、未確認、失敗、残課題を分けて記録する型。 配信報告テンプレート公開開発で実施したこと、判断、結果、次の一手を記録する型。

このプロジェクトが公開するもの

限界開発は完成品だけでなく、発想、聞き取り、要件整理、仕様化、実装、テスト、失敗、修正、公開、運用までを一つの流れとして残します。

使用したテンプレート・仕様書・PDF・構築方法も順次公開し、別の人が同じ流れを追試できる状態を目指します。
