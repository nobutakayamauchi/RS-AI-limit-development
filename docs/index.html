① はじめに

限界開発 仕様書目的、思想、対象課題、公開ルール、スマホから全工程を接続する構成、RTSとの関係。 リポジトリ概要基本方針、ディレクトリ構成、現在のEpisodeと運用方法。 公開開発の安全基準扱わない情報、本番利用前の確認事項、公開と実運用の境界。 AI開発基盤 RTS仕様、判断、ログ、検証、ガバナンスを接続する共通基盤。

② 現在の構成と再現方法

現在は、iPhoneからChatGPT・Codex・GitHub・Termiusを操作し、Oracle Cloud上のUbuntuで実行・テスト・ログ確認を行い、GitHub Pages・note・Xへ接続しています。

iPhone ├─ ChatGPT / Codex ─ 仕様・実装・レビュー ├─ GitHub ─ コード・仕様・履歴・Pages ├─ Termius ─ SSH ─ Oracle Cloud Ubuntu │ ├─ Python / CLI │ ├─ テスト │ └─ ログ・更新・Git操作 ├─ Safari ─ 公開ページ・実機確認 ├─ note ─ 開発記録 └─ X ─ 告知・相談受付
環境・接続構成・置き換え方Oracle CloudとTermiusを含む現在の実構成、各ツールの役割、最小構成、再現条件を確認する。 好きなツールへ置き換えるAI、クラウド、SSH、公開先、記録媒体を役割ごとに別サービスへ交換できます。 限界開発の詳細仕様何を満たせば限界開発と呼べるのか、設計原則と運用境界を確認する。
限界開発の構築手順環境準備から最初の公開までを通すガイド。現在整理中です。

再現すべきものは商品名ではありません。相談、問題分解、仕様化、実装、テスト、確認、記録、公開を一つの流れとして接続することです。

③ 実際に使うテンプレート

インタビューテンプレート相談内容を安全に聞き取り、課題と公開可能範囲を絞る型。 仕様書テンプレート目的、入力、出力、制約、最低成功条件を固定する型。 テスト報告テンプレート確認済み、未確認、失敗、残課題を分けて記録する型。 配信報告テンプレート公開開発で実施したこと、判断、結果、次の一手を記録する型。

このプロジェクトが公開するもの

限界開発は完成品だけでなく、発想、聞き取り、要件整理、仕様化、実装、テスト、失敗、修正、公開、運用までを一つの流れとして残します。

使用したテンプレート・仕様書・PDF・構築方法も順次公開し、別の人が自分の好きな道具へ置き換えながら追試できる状態を目指します。
