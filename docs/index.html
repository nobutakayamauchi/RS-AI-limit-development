① 限界開発を理解する

限界開発 仕様書目的、思想、対象課題、公開ルール、設計原則、RTSとの関係。 リポジトリ概要全体構成、Episode、テンプレート、運用方法。 公開開発の安全基準扱わない情報、本番利用前の確認、公開と実運用の境界。 AI開発基盤 RTS仕様、判断、検証、ガバナンスを接続する共通基盤。

② 現在の環境を再現する

現在は、iPhoneからChatGPT・Codex・GitHub・Termiusを操作し、Oracle Cloud上のUbuntuで実行・テスト・ログ確認を行っています。

iPhone ├─ ChatGPT / Codex ─ 仕様・実装・レビュー ├─ GitHub ─ コード・仕様・履歴・Pages ├─ Termius ─ SSH ─ Oracle Cloud Ubuntu │ ├─ Python / CLI │ ├─ テスト │ └─ ログ・更新・Git操作 ├─ Safari ─ 公開ページ・実機確認 ├─ note ─ 開発記録 └─ X ─ 告知・相談受付
環境・前提条件・置き換え方現在の実構成、役割分担、最小構成、好きなサービスへの置き換え方法。 限界開発の構築手順準備、仕様化、実装、Oracle Cloudでのテスト、公開、引き継ぎまで。 RTSとの接続方法Episodeの仕様・判断・テスト・引き継ぎを共通基盤へ接続する。 GitHub Pages 作成ガイド入口ページの作成、画像配置、Pages設定、スマホ確認、よくある失敗。

再現すべきものは商品名ではなく、相談、分解、仕様化、実装、テスト、確認、記録、公開を一つの流れとして接続することです。

③ 実際に使うテンプレート

④ Episode 001で追試する

試作品を開く未対応案件の抽出、期限分類、担当者集計、報告文生成。 仕様書相談から要件をどう固定したか。 テスト記録自動テストとスマホ実機確認、未確認事項。 引き継ぎ書現在地、残課題、次回作業を別セッションへ渡す。

⑤ 完成記録・開発日誌
