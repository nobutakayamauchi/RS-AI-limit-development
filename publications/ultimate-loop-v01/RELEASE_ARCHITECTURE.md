# Ultimate Loop v0.1 — Public Release Architecture

Status: `PRE_MERGE / HUMAN_VISUAL_APPROVAL_REQUIRED / NOT_PUBLISHED`

## Placement verdict

- **Public home:** Limit Development GitHub Pages.
- **Canonical technical source:** RTS `thin-rts/ULTIMATE_LOOP_METHOD.md`.
- **RTS Evolution:** supporting subsystem/context, not the public root of Ultimate Loop.

Ultimate Loop grew from Limit Development and now governs the broader development sequence. Putting the public story only under RTS Evolution would make a general development method look like one subsystem of RTS. Duplicating the full canonical specification into Limit Development would create two authorities. Therefore the public page explains and links; RTS owns canonical technical truth.

## WITNESS release boundary

1. Preserve the original outcome: prepare public material up to the human publish boundary.
2. Preserve `UNKNOWN / CONFLICT`: `DRAFT_READY != REVIEWED != PUBLISHED`.
3. Canonical truth is explicit: RTS owns the method; Limit Development owns the public narrative.
4. Material visual changes require human review before the live homepage is replaced.
5. Rejected layouts and corrected claims remain revision history.

## Social publication invariant

`PREPARED != PUBLISHED`

No X/API auto-posting, bulk posting, continuous posting, automatic threads, scheduled posting, retry loops, or automatic final Publish action. Native/manual platform controls remain external.

## Homepage design rules

- Preserve the current Limit Development hero and fixed definition.
- Do not replace the top with a giant “all results” billboard.
- Add a compact `LATEST UPDATE` strip below the hero.
- Add quick-jump cards for `Current / Method / Systems / Publications / Reproduce / History`.
- Give Ultimate Loop a concise homepage card plus a dedicated detail page.
- Add future releases as cards/timeline entries instead of continuously expanding the hero.
- Smartphone-first layout.
