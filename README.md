# RS-AI-limit-development

スマホ1台とAIで公開開発を行う「限界開発」シリーズの試作品・仕様書・検証記録です。

## 限界開発とは

リスナーや相談者が抱える「毎日めんどくさい作業」を公開配信で聞き取り、秘密情報を使わずに業務を分解し、架空のサンプルデータだけで最小試作品を作る公開開発シリーズです。

このリポジトリは完成品だけを並べる場所ではありません。仕様、判断、試行、失敗、テスト結果、未確認事項、次の一手まで残し、どのように作ったかを後から追える状態にします。

## 基本方針

- スマートフォンからAI開発環境を動かす
- 公開配信で説明しながら作る
- 未確認事項を勝手に事実として補わない
- 実在データではなく架空のサンプルデータを使う
- 最初から本番システムを約束しない
- 最低成功条件を先に定める
- 問題が起きた場合は、重要度の低い機能から削る
- 実行していない処理を「確認済み」と表現しない
- サンプルで動いたことと、本番導入可能であることを区別する

## 公開配信の安全ルール

公開配信では、次の情報を扱いません。

- 会社名、顧客名、利用者名、実在する個人名
- メールアドレス、電話番号、住所
- 医療・介護情報
- 社内URL、ID、パスワード、APIキー
- 実際の顧客データ、非公開の売上情報、社外秘資料

実際の業務へ導入する場合は、配信後にデータ形式、権限、利用規約、安全性、運用方法等を改めて確認します。

## エピソードの流れ

1. 安全確認
2. 悩みの聞き取り
3. 現在の作業を分解
4. 理想と最低成功条件を定義
5. 仕様書を固定
6. 専用ブランチで実装
7. サンプルデータでテスト
8. 確認済み事項と未確認事項を分けて記録
9. 必要に応じてPull Requestでレビュー

## ブランチ運用

配信回ごとに専用ブランチを使用します。

```text
episode/YYYY-MM-DD-short-name
```

第一回のブランチ：

```text
episode/2026-07-31-unhandled-case-report
```

`main`には、最低成功条件と記録が確認できたものだけを取り込みます。配信中の作業を自動でpush、merge、公開する運用にはしません。

## 本番利用について

このリポジトリの成果物は、原則として公開デモ用の試作品です。サンプルとして設定した条件で動作しても、本番データや実際の業務環境で利用できることを保証しません。

本番導入前には、少なくとも以下を確認します。

- 実際のデータ形式と列名
- 日付形式と文字コード
- データ量
- 個人情報・秘密情報の有無
- 利用端末と利用人数
- 保存、権限、バックアップの要否
- 外部サービス連携
- セキュリティと利用規約
- 運用担当者とエラー時の対応
