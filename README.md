# RS-AI-limit-development

> **限界開発 公式ページ**  
> https://nobutakayamauchi.github.io/RS-AI-limit-development/

スマホを司令塔としてAI・GitHub・クラウド実行環境を接続し、相談、仕様化、実装、デバッグ、公開までを一つの流れで回す「限界開発」の仕様・試作品・検証記録です。

## 現在の中核

### 限界開発式デバッグエンジン

UI実装が始まった時点から、画面・状態・ボタンの接続を記録し、人間の通常操作・偶発誤操作・意図的破壊操作を再現可能なテスト資産へ変換します。

- 文面から操作意図と確認目的を分類
- 一度踏んだ不具合を回帰テストへ固定
- 画面スクリーンショットとボタン接続先を視覚マップ化
- 全体マップが密集した場合は画面別マップへ自動分割
- リリース前に自動テストと人間専用テストを必須化
- 共通化できる欠陥をナレッジへ継続昇格

## 基本方針

- スマートフォンからAI開発環境を動かす
- 最低成功条件と非対象を先に定める
- 未確認事項を事実として補わない
- 実在する秘密情報を公開開発へ持ち込まない
- 実行していない処理を確認済みと表現しない
- サンプルで動くことと本番導入可能性を区別する
- UIは画面単位ではなく状態単位で管理する
- UI実装開始時点からデバッグエンジンを接続する
- 重大な操作不能・データ消失・接続不一致を残して公開しない

## 標準フロー

1. 安全確認
2. 悩みと目的の聞き取り
3. 作業と判断の分解
4. 最低成功条件の固定
5. 専用ブランチで実装
6. UI開始時に画面・操作台帳と視覚マップを作成
7. 正常系・破壊操作・復帰テスト
8. 修正後の回帰テスト
9. 自動テストと人間専用テストによるリリースゲート
10. 公開・引き継ぎ・ナレッジ更新

## 公開前の停止条件

次のいずれかが残る場合はリリースしません。

- 操作不能・進行不能
- データ消失・復元不能
- 誤完了・二重実行
- 期待接続先と実測接続先の不一致
- 表示状態と内部状態の重大な不一致
- プレビューと最終成果物の重大な差異
- 人間専用テスト未実施

## 安全と本番利用

公開開発では、個人情報、認証情報、医療・介護情報、社外秘、実在顧客データを扱いません。本番導入前には、データ形式、権限、保存、バックアップ、外部サービス、セキュリティ、規約、運用担当を別途確認します。
