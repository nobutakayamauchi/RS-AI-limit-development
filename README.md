# RS-AI-limit-development

> **限界開発の公式ページ**  
> https://nobutakayamauchi.github.io/RS-AI-limit-development/

スマホ1台とAIで公開開発を行う「限界開発」シリーズの試作品・仕様書・検証記録です。

## 限界開発とは

リスナーや相談者が抱える「毎日めんどくさい作業」を公開配信で聞き取り、秘密情報を使わずに業務を分解し、架空のサンプルデータだけで最小試作品を作る公開開発シリーズです。

このリポジトリは完成品だけを並べる場所ではありません。仕様、判断、試行、失敗、テスト結果、未確認事項、次の一手まで残し、どのように作ったかを後から追える状態にします。

## 基本方針

- スマートフォンからAI開発環境を動かす
- 公開配信で説明しながら作る
- 未確認事項を勝手に事実として補わない
- 実在データではなく架空のサンプルデータを使う
- 最初から本番システムを約束しない
- 最低成功条件を先に定める
- 問題が起きた場合は、重要度の低い機能から削る
- 実行していない処理を「確認済み」と表現しない
- サンプルで動いたことと、本番導入可能であることを区別する
- 安全性を確認できない入力は、料金計算や実行へ進めない
- 課金・外部変更・公開を伴う処理は、内容と上限を表示し、1回ごとの明示承認後にだけ実行する

## 限界開発の実行ゲート

入力や命令を受け取っただけでは処理を始めません。外部サービス、課金、公開、書き込み、重い処理へ進む経路は、必ず次の順序を通します。

```text
入力
↓
Security Gate
↓
Cost / Consequence Gate
↓
明示的な1回限りの承認
↓
承認範囲内の実行
↓
結果確認・監査記録
```

Security Gateでは、画像・動画・音声・文書・アーカイブ・表データだけでなく、ファイル名、拡張子、MIME、メタデータ、マニフェスト、入力文、URL、実行引数も未信頼入力として扱います。

- 許可した形式と構造だけを通す
- 拡張子と実体の不一致を拒否する
- 容量、解像度、尺、ストリーム数、展開後容量、処理時間へ上限を設ける
- 入力をシェルコマンドへ文字列連結しない
- ファイル名とパスを内部IDへ置換する
- 不要なメタデータや能動的内容を除去する
- 判定不能は合格にせず、隔離または拒否する
- 合格した入力のハッシュへ、見積もりと承認を結び付ける

Cost Gateでは、利用先、対象、入力容量、CPU・メモリ・モデル、最大時間、並列数、再試行、転送・保存、予想上限額、外部への影響を表示します。初期値は「並列1・自動再試行なし・時間と容量を制限・有料先への自動フォールバックなし」です。

承認は、対象・入力ハッシュ・実行条件・利用先・上限額へ紐づく1回限りのものです。入力や条件が変われば、Security Gateからやり直します。

## 非常用の計算退避

スマホや通常サーバーの能力では完走できない重処理だけ、手動で外部計算環境へ逃がす場合があります。

これは通常構成ではなく、**非常用オーバーフロー処理**です。

- 自動では切り替えない
- 通常処理が能力不足で完走できない場合だけ選ぶ
- 毎回Security Gateを通す
- 毎回料金と条件を確認する
- 毎回明示承認を取る
- 同時実行と再試行を最小化する
- 外部ワーカー障害で通常画面や記録系を巻き込まない

## 公開配信の安全ルール

公開配信では、次の情報を扱いません。

- 会社名、顧客名、利用者名、実在する個人名
- メールアドレス、電話番号、住所
- 医療・介護情報
- 社内URL、ID、パスワード、APIキー
- 実際の顧客データ、非公開の売上情報、社外秘資料

実際の業務へ導入する場合は、配信後にデータ形式、権限、利用規約、安全性、運用方法等を改めて確認します。

## エピソードの流れ

1. 公開・秘密情報の安全確認
2. 入力と命令のSecurity Gate設計
3. 悩みの聞き取り
4. 現在の作業を分解
5. 理想と最低成功条件を定義
6. 仕様書を固定
7. 専用ブランチで実装
8. 無料・ローカルの検査とテスト
9. 課金や外部変更がある場合は見積もり表示と明示承認
10. 承認された範囲だけ実行
11. 確認済み事項、費用、未確認事項を分けて記録
12. 必要に応じてPull Requestでレビュー

## ブランチ運用

配信回ごとに専用ブランチを使用します。

```text
episode/YYYY-MM-DD-short-name
```

`main`には、最低成功条件、安全ゲート、記録が確認できたものだけを取り込みます。配信中の作業を自動でpush、merge、公開する運用にはしません。

## 本番利用について

このリポジトリの成果物は、原則として公開デモ用の試作品です。サンプルとして設定した条件で動作しても、本番データや実際の業務環境で利用できることを保証しません。

本番導入前には、少なくとも以下を確認します。

- 実際のデータ形式と列名
- 日付形式と文字コード
- データ量
- 個人情報・秘密情報の有無
- 利用端末と利用人数
- 保存、権限、バックアップの要否
- 入力の隔離、検査、無害化、監査
- 外部サービス連携と費用上限
- セキュリティと利用規約
- 運用担当者とエラー時の対応
